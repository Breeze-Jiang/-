# 沿途 Android 前端第二轮设计说明

## 目标

把已确认的产品规划和设计预览转为一个可运行的 React Native Android 应用。用户无需登录即可完成地图找点、查看地点可信信息及选择导航方式；需要写入或社交的动作在触发时再登录，并保留原操作的上下文。

## 范围与分层

本轮将客户端分为五个根入口：地图、发现、消息、收藏、我的。详情、创建、聊天、导航、审核和账户页面由根栈承载，进入这些页面时不显示底栏。页面使用演示数据和显式状态，服务端接口接入不在本次 UI 重构中伪造业务事实。

## 视觉方向

使用浅色、高留白、品牌蓝 `#246BDF`、可信绿 `#149B80`，以 4dp 间距和 12–24dp 圆角形成轻盈但不轻浮的界面。地图页的“沿途服务”作为签名元素，以完整服务面板而非隐藏入口呈现。所有结构性图标先用可替换的单色符号组件，避免将 emoji 作为正式导航图标。

## 核心闭环

1. 地图页：定位/搜索/服务入口 → 距离优先的地点结果。
2. 地点详情：地点事实、营业时间、最近确认、收藏、分享、导航。
3. 导航：步行、骑行、驾车、公交地铁、打车跳转；驾车使用低干扰专属视图。
4. 发现：推荐与公开论坛；公开下提供资源、标注、计划三频道及固定发布入口。
5. 资产与同行：私密标注、收藏夹、计划、消息、好友、位置共享、审核通知均有明确入口与空/异常状态。

## 前端边界

- 可信状态只展示数据对象所携带的事实和时间，不以视觉推断“实时可用”。
- 标注与计划默认私密；公开相关操作必须显示审核语义。
- 登录拦截不替代游客浏览。认证成功后的动作由待续办状态恢复。
- 首发不实现真实订单、支付、陌生人群聊或离线地图。

## 验收方式

在 Android 模拟器/真机中从游客态启动：底栏完整可见；各根模块能进入对应详情；地图服务可进入结果、详情与导航；写入型操作显示登录续办；页面在无数据和网络失败状态下提供可理解的恢复动作。代码通过 TypeScript/ESLint 和 Android 构建检查后，逐页对照 `design/DESIGN_SYSTEM.md` 与总规划审计。
