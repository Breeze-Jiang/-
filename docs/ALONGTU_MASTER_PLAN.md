## 0. 新协作窗口快速交接（必读）

### 一句话定义

**沿途不是普通地图 App，而是“旅游便利服务 + 旅游资源标注 + 旅游攻略社区 + 可执行旅游计划”的旅行工具。**

### 绝不能丢失的产品优先级

1. **旅游便利是第一核心。** 用户在陌生城市急需厕所、停车、补能、药店、医院、便利店或警务点时，要能迅速找到可信地点并开始导航。
2. **旅游资源标注是第二核心。** 用户要能记录值得去、好用或避坑的地点，收藏、下次导航、分享好友，并按可见范围管理。
3. **论坛讨论旅游攻略和旅游资源是第三核心。** 地点帖以照片为主，旅行讨论帖以文字为主；它们不是普通社交动态，而是让旅游经验沉淀为可发现资源。
4. **旅游计划是第四核心。** 用户既能手动编排行程，也能用 AI 生成可编辑草稿，或复制公开计划；计划要连接地点、路线与导航，而非做成普通待办清单。
5. **地图只是承载方式，不是产品终点。** 任何模块都应服务“旅行时更快解决问题、发现地点、记录、规划和分享经验”。

### 当前设计重点（2026-07-16 确认）

除旅游便利地图的 P0 闭环外，**发现模块与旅游资源标注是本项目的重点卖点，后续设计和前端交接优先级高于一般社交装饰功能。**

1. **发现模块：** 以可持续阅读的旅行内容流为主，重点完成推荐、公开论坛、问答详情、目的地/话题筛选、发布、搜索、作者主页和异常状态；旅行资源、讨论与公开计划必须各自有正确的阅读和下一步动作。
2. **旅游资源标注：** 重点完成从地图选点、新建标注、默认私密保存、好友定向分享、公开资料补充、内容/地点审核、公开帖子、公共地图推荐，到编辑、撤回、纠错与失效提示的完整闭环。
3. **两者的联动：** 用户应能从地图发现地点后创建标注；从发现页读到资源后查看地点并导航；合规公开标注可沉淀为论坛资源，达到后台门槛并经人工审核后才进入公共地图。任何一个入口都不得绕开可见范围、审核状态或地点可信信息。

底部根导航统一为 **地图｜发现｜消息｜收藏｜我的**；标注不新增第六个导航项，而是通过地图“＋ 标注此处”、发现“热门标注分享”和我的“我的标注”三个入口突出。具体视觉与跳转规则见 `design/BOTTOM_NAV_SPEC.md`。

设计优先级说明：聊天、群聊、个人主页的基础可用性仍需保持，但不应抢占发现阅读流、资源标注详情、标注公开审核和地图/导航联动的设计资源。

## 1. 产品定位

**沿途**是面向中国大陆年轻自由行用户和自驾游客的旅游便利地图与地点社区应用。

它首先解决旅游中的即时需求：用户身处陌生城市时，应能在约 10 秒内找到附近可信、可导航的厕所、停车场、加油站、充电站等设施。其后，用户可以发现值得去的地点，收藏与自定义标注，并把旅游资源和攻略分享给朋友或发布到社区讨论。

宣传语：**找到所需，记下所爱，分享所见。**

### 核心卖点

1. **旅游便利优先**：不仅是普通地图搜索；首页和服务中心针对旅途中的急需设施与补给资源优化。
2. **旅游资源标注**：用户可记录有趣、实用或避坑的地点，默认私密，可按规则分享给好友或社区。
3. **旅游论坛与资源讨论**：地点帖以照片为主，旅行讨论帖以文字为主；支持按城市、标签、作者和地点发现内容。
4. **可信地点信息**：首发明确展示地点存在、营业时间与用户最近确认时间，不虚构“实时可用”。
5. **从个人标注到公共地图**：合规公开地点达到后台配置的收藏门槛后，进入人工推荐审核；通过后才投放公共地图。

## 2. 首发边界

### 已确认

- 首发地区：中国大陆。
- 首发客户端：Android 优先；iOS 后续适配。
- 使用方式：首发要求联网；离线地图、离线资源包为后续版本。
- 导航：优先支持应用内导航；也支持跳转高德、百度、腾讯等外部地图，具体供应商由实现阶段统一抽象与配置。
- 出行方式：步行、骑行、驾车、公交地铁、打车。
- 打车定位：作为地点详情与路线选择中的出行方式入口；首发仅对接或跳转第三方叫车服务，不自建司机、订单、支付、客服或调度体系。
- 游客优先：浏览、搜索、查看详情和导航无需登录。
- 按需登录：收藏、创建标注、确认信息、分享、发帖、评论、关注、加好友、聊天和位置共享时再要求登录。
- 登录方式：手机号验证码、微信登录、密码登录。
- 品牌：名称为“沿途”；当前使用双字精修版 v7（品牌蓝圆角方形 + 白色“沿途”横排字标），Logo 不阻塞功能开发。
- 旅游计划：支持手动创建、AI 生成可编辑草稿、浏览/复制公开计划，以及由作者主动公开自己的计划；默认仅自己可见。

### 不纳入首个核心闭环

- iOS 正式适配。
- 深色模式。
- 离线地图和离线资源包。
- 面向陌生人的群聊、付费、广告、商家入驻与交易。
- 基于完整历史轨迹的行程回放。

## 3. 用户与核心场景

### 主要用户

- 年轻自由行游客：需要景点、餐饮、便利设施和旅行经验。
- 自驾游客：需要加油、充电、停车、补给、酒店及驾驶导航。
- 与朋友结伴的游客：需要共享地点、私聊、群聊和临时实时位置共享。

### 北极星场景

游客在陌生城市突然需要上厕所：打开沿途后，在约 10 秒内找到最近且信息可信的厕所，并开始导航。

### 关键旅程

1. 打开地图 → 授权定位 → 点击服务类别或搜索 → 查看最近结果 → 查看可信状态 → 选择方式并导航。
2. 发现地点或服务 → 查看详情、开放时间、最近确认与社区内容 → 收藏到默认或自定义收藏夹。
3. 创建标注 → 填名称和定位点 → 选择可见范围 → 私存、分享好友或提交公开审核。
4. 浏览发现页 → 按城市、标签或搜索筛选 → 查看地点帖/旅行讨论帖 → 收藏、点赞、评论、关注、举报或分享。
5. 好友聊天或私密群 → 分享地点卡片 → 自愿加入实时位置共享 → 任意人退出自身共享；发起者退出即关闭本次共享。
6. 新建旅游计划 → 手动从地图/收藏/标注/论坛加入地点，或填写目的地、天数、方式和偏好由 AI 生成草稿 → 调整每日顺序与路线 → 对单个地点或当天行程发起导航。
7. 浏览公开旅行计划 → 查看路线与地点依据 → 复制为自己的私密计划并继续编辑；原作者可选择公开、更新或撤回。

## 4. 信息架构与客户端模块

首发根导航为五栏：**地图｜发现｜消息｜收藏｜我的**。详情、编辑、聊天、导航、审核与实时位置共享页面使用独立栈，不显示底部栏。

### 4.1 地图与旅游便利服务

- 搜索地点、地址、城市和标签。
- 固定直达入口：厕所、加油站、充电站、超市、景点、酒店。
- 突出“沿途服务”入口：停车场、充电宝、药店、医院、便利店、警务点、美食等。
- 地图搜索结果默认按距离优先；支持营业中、最近确认、设施条件等筛选。
- 加油站与充电站分别保留入口，不合并；可按车辆类型做推荐排序，但不可隐藏任一入口。
- 地点详情展示名称、坐标/地址、距离、营业时间、可信状态、用户最近确认、导航、收藏、分享与关联内容。
- 公共地图按当前位置或浏览城市推荐；按缩放级别、城市、区域及同屏上限投放，防止地图拥挤。

### 4.2 导航

- 应用内步行、骑行、驾车、公交地铁导航状态与异常恢复，以及打车第三方服务跳转状态。
- 驾车提供专用驾驶模式：大字号、低干扰、关键信息优先；不承载社区操作。
- 导航前允许切换方式和外部地图。
- 位置权限、无定位、网络异常、路径失败、目的地关闭等必须提供可恢复动作。

### 4.3 发现与论坛

- 发现顶级导航固定为 **推荐｜公开**；可点击切换，也支持横向滑动切换。
- **推荐**为个性化旅游资源流：综合最近搜索/浏览/收藏的目的地、当前位置或浏览城市、内容质量与用户明确选择的偏好，混合展示地点标注帖、旅行讨论帖与公开旅行计划。必须给出简洁可理解的推荐原因，并允许改为附近、全国热门或最新，不能把推荐做成不可调整的黑箱。
- **公开**为可持续浏览的公共旅游论坛；其二级导航固定为 **热点旅游资源｜热门标注分享｜旅游计划探讨**。用户可通过级联地点选择器按全国、城市、商圈/景区逐层筛选，也可直接搜索具体景点；再叠加资源类别、热门/最新等筛选。
- 信息流、城市筛选、标签筛选、搜索、地点详情联动。
- 地点标注帖：照片优先，展示地点、图片、实用描述、可信/审核状态。
- 旅行讨论帖：文字优先，适合攻略、避坑、路线、提问和经验交流。
- 公开旅行计划：路线/日程摘要优先，展示目的地、天数、出行方式、地点数、作者、公开范围与互动；主要动作是查看和复制为我的计划。
- 支持收藏、点赞、评论、关注作者、举报与分享。
- 首发必须具备内容空态、审核中、审核不通过、删除/不可见与网络失败状态。

### 4.4 标注、收藏与个人资产

- 新建标注必填：名称、定位点。
- 公开到论坛时额外必填：文字描述、照片；照片需保留地点和时间证据，用于审核。
- 选填：分类、开放时间、适合人群、消费水平、注意事项、标签等。
- 新建标注默认仅自己可见；可选仅自己、指定好友、全部好友、公开到论坛。
- “我的标注”默认列表优先、可切换地图；支持按城市/区县、自定义收藏夹、草稿、可见范围、公开审核状态与需补充资料筛选。每项展示地点、照片/缩略图、距离或城市、最后确认/更新时间、可见范围和独立审核状态。
- 标注详情提供编辑、导航、分享、修改可见范围、撤回公开、删除和地点纠错；编辑、删除、改权限或撤回公开后，旧公开索引、分享访问和地图缓存必须按权限一致失效。
- 收藏按城市/区县自动归类，并支持用户创建收藏夹；地点列表默认距离优先。
- 收藏夹可参考短视频应用的收藏组织方式，但不得复制其视觉资产或交互文案。

### 4.5 旅游计划

- 计划可由用户手动创建，也可由 AI 根据目的地、日期/天数、出行方式、偏好和可选补充要求生成**可编辑草稿**；AI 不得自动发布计划、虚构地点信息或覆盖用户修改。
- 手动创建时可从地图搜索、收藏、个人标注、地点详情、论坛地点帖和公开计划加入地点；计划按天组织，每日地点顺序变化后应重新计算路线摘要。
- 每个计划地点必须保留可打开的地点/内容引用；用户可替换、删除、调整顺序、添加备注，并从地点或当天行程进入导航。
- 计划默认仅自己可见；可选指定好友、全部好友或公开社区。公开前必须允许隐藏真实出发日期、实时位置、同行人、私密地点和私人备注；公开界面默认以“第 1 天/第 2 天”表达日程，而非暴露精确行程日期。
- 公开计划进入“公开｜旅游计划探讨”，支持浏览、点赞、评论、收藏、分享和“复制为我的计划”。复制后生成独立私密副本，永不反向修改原计划；原作者可更新、撤回公开或删除原公开版本。
- 公开计划仅进入论坛内容审核；其中含有的地点不会因此自动获得地点公开资格或公共地图推荐资格。

### 4.6 关系、消息与实时位置

- 好友和关注是独立关系。
- 首发关系能力：加好友、好友主页、向好友定向分享标注、通知中心。
- 聊天能力：私聊、仅好友可邀请的私密群、地点卡片分享、会话列表。
- 实时位置共享：用户主动加入、可自行退出、仅当前参与者可见；发起者退出则关闭整场；不保存完整历史轨迹。
- 群聊需要邀请、成员、举报、退出、解散、违规处理和位置异常状态设计；不开放陌生人广场群。

### 4.7 我的与通知

- 个人主页、我的标注、旅游计划、帖子、收藏、关注/好友、设置、隐私与权限说明。
- 通知覆盖点赞、评论、关注、好友申请、地点/计划分享、审核结果和群聊邀请。

## 5. 可信信息与三层审核

三层审核必须是独立流程，不能用单一“审核状态”混合表达。

### 第一层：论坛内容审核

- 对象：地点帖、旅行讨论帖、公开旅行计划、评论及媒体内容。
- 检查：文字、图片、违法违规、广告垃圾、隐私与内容安全。
- 讨论帖和公开旅行计划只走此流程；公开旅行计划不因被审核通过而自动公开其包含地点，也不进入公共地图推荐流程。

### 第二层：标注点基础公开审核

- 对象：申请公开的地点标注。
- 检查：地点是否存在、坐标合理性、照片地点/时间证据、公开资料完整性。
- 私密和好友可见标注不参与该流程。
- 地点帖要同时通过内容审核与标注点基础公开审核，才能公开到论坛。

### 第三层：公共地图人工推荐审核

- 触发：合规公开地点的收藏数达到后台配置门槛。
- 检查：是否具有公共价值、资料是否持续可信、是否适合投放。
- 通过后创建公共地图投放记录；投放范围受城市、区域、缩放级别和同屏数量控制。
- 推荐未通过不下架已合规的论坛帖子；撤回公共地图投放不等于删除帖子或地点。
- 收藏门槛必须后台配置，不能把“100 收藏”写死在客户端或业务代码中。

## 6. 核心数据实体与关系

下列实体应独立建模，避免把不同生命周期塞进同一张表。

| 领域 | 核心实体 | 说明 |
| --- | --- | --- |
| 身份 | User、AuthIdentity、DeviceSession | 手机、微信、密码与会话分离；密码仅保存安全摘要。 |
| 地图 | Place、PlaceSource、PlaceCategory、PlaceOpeningHours | 地点主数据、来源、分类、营业时间。 |
| 可信 | PlaceConfirmation、PlaceEvidence | 用户确认与审核证据；记录来源、时间、结果与可见性。 |
| 用户标注 | Marker、MarkerMedia、MarkerVisibilityGrant | 标注与媒体独立；可见范围不靠字符串硬编码。 |
| 收藏 | Favorite、FavoriteFolder、FavoriteFolderItem | 支持默认城市归类与自定义收藏夹。 |
| 社区 | Post、PostMedia、Comment、Like、Follow、Report | 地点帖与讨论帖由 Post.type 区分，但审核状态独立。 |
| 旅游计划 | TravelPlan、TravelDay、TravelPlanItem、TravelPlanVisibilityGrant、TravelPlanPublication | 计划、按天日程、地点/内容引用、可见范围与公开版本独立；复制计划必须生成新的计划所有权与条目。 |
| 审核 | ModerationCase、PlacePublicReview | 内容审核与地点公开审核分开记录。 |
| 推荐投放 | RecommendationApplication、PublicMapPlacement | 推荐资格、人工审核、地图投放独立。 |
| 社交 | Friendship、Conversation、ConversationMember、Message | 好友、私聊与群聊分层。 |
| 实时位置 | LiveLocationSession、LiveLocationParticipant、LiveLocationPing | 会话级授权；限制留存，不做轨迹产品。 |
| 平台 | Notification、AuditLog、FeatureConfig | 通知、重要操作审计、门槛和投放配置。 |

所有地点类实体都必须使用标准坐标字段、坐标系约束、城市/区县归属与地理索引；经纬度不得以文本字段替代。

## 7. 权限、隐私与安全

- 定位、相机、相册、通知权限均按场景申请；拒绝后提供替代流程和设置入口。
- 仅导航或浏览不强制登录；每次写入或社交操作登录成功后应自动续办原操作。
- 标注默认私密，公开范围可随时收回；收回后客户端地图缓存和可访问索引需失效。
- 聊天分享的地点卡片只存内容引用；打开私密内容时服务端重新鉴权。
- 实时位置只向会话参与者发送，使用会话有效期、退出和发起者关闭机制；不默认为历史轨迹。
- 举报、封禁、审核和位置共享关闭操作必须写入审计日志。
- 照片公开审核所需的地点/时间证据应最小化存储与展示，避免把敏感 EXIF 原样公开给其他用户。

## 8. 现有工程事实与后端技术基线

### 现有工程事实

- 客户端现有工程为 React Native + TypeScript，已有导航、状态管理、地图、图片选择和网络请求依赖。
- 旧 Python + FastAPI 服务端及其旧启动、部署文件已删除，不再作为实现或兼容目标。
- 新服务端为 Go 模块化单体，使用 chi、pgx/sqlc、PostgreSQL/PostGIS、Redis、Goose、OpenAPI 和 Docker Compose。
- 高德是 P0 主地图/路线供应商，但通过内部适配层隔离；业务实体和公开 API 不暴露供应商私有字段。
- 当前只实现 P0 所需的最小手机号会话、地点、可信确认、路线和第三方导航/叫车跳转边界。

### 已确认的 P0 技术决策

1. 采用 Go 模块化单体，不提前使用微服务；HTTP API 和管理指标使用独立监听地址。
2. PostgreSQL/PostGIS 保存永久事实与空间数据；Redis 只保存验证码、限流、短期缓存和熔断状态。
3. API 使用 `/api/v1`、REST/JSON、统一错误结构和 OpenAPI 契约。
4. 高德负责 P0 POI 与四类路线；步行、骑行、驾车、公交地铁使用统一内部路线模型。
5. 打车只提供可配置的第三方跳转边界，不建设司机、订单、支付、客服和调度系统。
6. Android 首发；后端 API 和领域模型保持客户端平台无关。
7. 当前生产目标为阿里云单区域、小团队生产级和 99.9% 月可用性，不建设异地双活。

### 已确认的后端业务约束（不等于技术选型）

- 地图供应商能力必须可替换，不能将业务实体绑定在某一家供应商的返回字段上。
- 打车服务同样必须通过可替换的第三方适配/跳转边界接入；业务侧只表达“可叫车/不可叫车/跳转失败”等状态，不承载订单履约。
- 地点、标注、帖子、审核申请和公共地图投放是独立业务实体。
- 收藏门槛、投放上限和审核策略必须可配置，不能在客户端写死。
- 地点类数据必须支持标准坐标、城市/区县归属和附近查询；具体索引技术待选型。
- 位置共享是短时、主动加入、可退出的会话能力，不默认保存完整轨迹。

### 候选业务 API 域（仅用于讨论范围，不代表接口已定）

- `/auth`：验证码、密码、微信身份接入、会话刷新、登出。
- `/places`：附近检索、搜索、详情、营业信息、确认、地图供应商适配结果。
- `/navigation`：路线请求、方式选择、外部跳转参数。
- `/ride-hailing`：第三方叫车可用性、跳转参数与失败状态；不包含司机、订单、支付或调度领域。
- `/markers`：创建、编辑、可见范围、媒体、分享、公开申请。
- `/favorites`：收藏、收藏夹、城市/区县分组。
- `/feed`、`/posts`：信息流、帖子、评论、点赞、关注、举报。
- `/reviews`：内容审核、地点公开审核、推荐审核与后台操作。
- `/friends`、`/conversations`、`/messages`：好友、会话、群成员、消息和地点卡片。
- `/live-location`：创建/加入/退出/关闭共享会话及位置心跳。
- `/notifications`、`/configs`：通知中心和只读业务配置。

## 13. 详细产品需求与行为规范

本节补充各模块的业务行为，供设计、客户端、后端和测试共同使用。未在本节明确的具体数值、供应商和技术实现均不视为已确认。

### 13.1 地图首页与旅游便利服务

#### 产品目标

让游客不用先去其他平台搜索旅游资源，再回到地图重新搜索。沿途服务入口要在地图首页可被第一眼发现，并能让用户理解“这里不仅是普通地图”。

#### 首页必须具备

- 顶部位置/城市入口与全局搜索框；搜索范围包括地点、服务、地址、城市和标签。
- 直接可见的六个服务入口：**厕所、加油站、充电站、超市、景点、酒店**。
- 高可见的“沿途服务”入口或上拉面板，承载停车场、充电宝、药店、医院、便利店、警务点、美食等服务；不可把它设计成难以发现的普通二级菜单。
- 地图当前定位、地图缩放、图层/视角控制和附近地点标记。
- 用户可通过点击服务、搜索、地图标记或地点卡片进入同一套地点结果与详情闭环。

#### 服务类别规则

| 类别 | 首发要求 | 说明 |
| --- | --- | --- |
| 厕所 | 固定直接入口 | 北极星急需场景；结果优先强调距离与最近确认。 |
| 加油站 | 固定直接入口 | 自驾补给，不能被充电站替代或隐藏。 |
| 充电站 | 固定直接入口 | 电动车补能，不能被加油站替代或隐藏。 |
| 超市 | 固定直接入口 | 旅途补给。 |
| 景点 | 固定直接入口 | 旅游探索入口，承接地点内容与收藏。 |
| 酒店 | 固定直接入口 | 住宿入口。 |
| 停车场、充电宝、药店、医院、便利店、警务点、美食 | 沿途服务中高可见 | 服务中心必须支持快捷筛选，不要求用户记住分类层级。 |

#### 结果排序与可信信息

- 默认排序是**距离优先**，不是热度优先；用户需要时可切换筛选。
- 首发“可信信息”只承诺三类：地点存在、营业时间、用户最近确认时间。
- “营业中”“可用”“空闲”“有位”等强实时表述，只有在有合法、可靠、可追溯的数据源时才显示；否则不得伪造实时状态。
- 用户确认应记录确认时间、确认类型和来源；详情页只展示用户应理解的摘要，不暴露个人敏感信息。
- 搜索无结果、定位不可用、网络失败、权限拒绝、数据加载中时，必须说明原因并提供原地重试、改城市、手动输入地点或打开系统设置等恢复动作。

### 13.2 地点详情与导航

#### 地点详情信息层级

1. 名称、类别、距离、地址/定位点。
2. 可信状态：地点存在、营业时间、最近确认；状态不应用颜色作为唯一信号。
3. 主操作：开始导航；次操作：收藏、分享、确认信息、查看关联地点帖/讨论。
4. 补充信息：开放时间、适合人群、消费水平、注意事项、标签、照片和用户内容。

#### 导航规则

- 支持步行、骑行、驾车、公交地铁、打车五种方式；默认方式可根据用户当前场景推荐，但必须允许手动切换。
- 应用内导航是优先能力；同时保留外部地图跳转选择。
- 打车方式仅负责将用户送入可用的第三方叫车服务；页面可以展示路线距离或预计车程，但价格、车型、司机位置和订单进度只能使用已获授权且可信的服务数据。
- 驾车模式是独立低干扰页面：大字号、关键转向和距离优先，禁止在驾驶中插入发帖、评论或复杂聊天操作。
- 从地点详情、收藏、好友分享卡片、帖子地点卡片进入导航时，均应保留原页面返回上下文。
- 导航失败、路线不可用、定位失效、网络中断或目的地异常时，不应丢失目的地和已选出行方式。

### 13.3 收藏与个人旅游资源

#### 收藏

- 收藏是地点资产，不要求登录前浏览者先注册；触发收藏时再引导登录，登录成功后自动续办。
- 收藏页按城市/区县组织，默认展示距离优先的地点；用户可以选择城市或进入自定义收藏夹。
- 用户可创建、重命名、排序和删除自定义收藏夹；删除收藏夹时不得误删地点本身或其他收藏夹中的同一地点。
- 收藏、标注和公开帖子是不同关系：收藏不等于创建标注，不等于公开推荐。

#### 自定义标注

- 创建入口可来自地图长按、地点详情、收藏和个人页。
- 必填字段：名称、定位点。
- 默认可见范围：仅自己；用户可改为指定好友、全部好友或公开到论坛。
- 公开到论坛时，必须补充文字描述和照片；公开照片需提供地点/时间审核证据，但用户前台不应被迫公开原始隐私元数据。
- 分类、开放时间、适合人群、消费水平、注意事项、标签均为可选；公开资源建议填写开放时间和适合人群。
- 标注编辑、删除、修改可见范围或撤回公开后，旧分享链接、地图缓存和公共可见索引必须按权限失效。

### 13.4 旅游论坛与资源沉淀

#### 内容类型

| 类型 | 内容主次 | 必须关联 | 适用内容 |
| --- | --- | --- | --- |
| 地点标注帖 | 照片优先 | 地点标注 | 宝藏地点、停车/补给经验、景观、避坑和实用资源。 |
| 旅行讨论帖 | 文字优先 | 无强制地点 | 攻略、路线、提问、目的地经验、结伴前的信息讨论。 |
| 公开旅行计划 | 路线/日程优先 | 旅行计划 | 可复制的多日路线、目的地玩法、出行方式与地点组合；不自动公开计划包含的私密地点。 |

#### 浏览与互动

- 发现一级导航为推荐和公开；公开页二级导航为热点旅游资源、热门标注分享和旅游计划探讨。支持信息流、城市/景点级联筛选、标签筛选、关键词搜索和作者主页。
- 用户可收藏地点、点赞帖子、评论、关注作者、举报和分享；具体是否增加“帖子收藏”可在后续讨论，不可与地点收藏混淆。
- 公开地点帖应能回到地点详情与导航；讨论帖可关联地点，但不强制；公开旅行计划可查看日程/路线并复制为个人私密副本。
- 论坛展示必须区分已公开、审核中、审核未通过、仅自己可见、好友可见和内容不可用状态。
- 举报入口必须可访问，且举报后给用户明确的提交结果，不承诺固定处理时限。

#### 发布规则

- 用户发布帖子、评论、点赞、关注、举报和分享前，如未登录，应走按需登录并返回原操作。
- 地点帖先经过内容审核与地点基础公开审核；两者都通过后才可在公开论坛中被发现。
- 旅行讨论帖只走内容审核，不进入地点基础公开审核或公共地图推荐流程。
- 公开旅行计划只走内容审核；作者须先选择公开范围与脱敏项，审核通过后才能出现在“旅游计划探讨”，且不能因此公开被隐藏地点或触发公共地图投放。

### 13.5 三层审核状态机

#### 论坛内容审核

状态建议：草稿 → 提交中 → 内容审核中 → 已公开 / 需修改或不通过 / 已下架。

#### 地点基础公开审核

状态建议：私密或好友可见 → 申请公开 → 地点审核中 → 允许公开 / 退回补充 / 拒绝公开。

#### 公共地图推荐审核

状态建议：公开且合规 → 达到后台门槛 → 推荐候选 → 人工审核中 → 已投放 / 未通过 / 已撤回投放。

关键约束：

- 地点帖公开前，内容审核和地点审核都必须通过。
- 公开帖子合规不表示必然成为公共地图推荐点。
- 推荐审核未通过不影响已合规公开帖继续存在。
- 公共地图投放撤回不等于删帖、删标注或取消用户收藏。
- 审核状态应包含用户可理解的原因摘要和下一步动作；后台详细证据与内部风控原因不得直接暴露。

### 13.6 好友、聊天与实时同行

#### 关系边界

- 好友与关注分开：关注用于内容发现；好友用于定向分享、私聊、群聊邀请与位置共享。
- 首发加好友应有申请、同意、拒绝、删除、拉黑/举报等基础边界；具体交互可以后续设计，但权限不应缺失。
- 好友主页展示的标注、帖子和收藏摘要必须遵从可见范围；不能因为成为好友就默认看到全部私密地点。

#### 消息与群聊

- 私聊支持文本、地点卡片与标注定向分享。
- 群聊仅限好友邀请进入的私密群；不做陌生人开放群广场。
- 群成员、入群邀请、退群、群解散、举报和消息不可用状态必须有清晰规则。
- 聊天中的私密地点卡片每次打开时需重新校验访问权限。

#### 实时位置共享

- 位置共享不是默认开启功能，用户必须主动创建或加入当前共享会话。
- 任一参与者可随时退出自身共享；发起者退出则关闭整场共享。
- 仅当前会话参与者可见实时位置；不提供默认完整历史轨迹回放。
- 位置共享页面应明确“正在共享给谁”“如何退出”“共享关闭后的行为”；位置异常、网络断开、定位权限收回需要明确状态。

### 13.7 登录、权限与游客体验

| 行为 | 是否需要登录 | 说明 |
| --- | --- | --- |
| 浏览地图、搜索、看地点详情、开始导航 | 否 | 游客核心体验不能被登录墙阻断。 |
| 收藏、创建/编辑标注、确认地点信息 | 是 | 需要归属到用户并留审计记录。 |
| 发帖、评论、点赞、关注、举报、分享 | 是 | 需要内容责任、反垃圾和通知能力。 |
| 加好友、私聊、群聊、位置共享 | 是 | 需要关系和隐私授权。 |

- 登录方式：手机号验证码、微信、密码。
- 定位、相机、相册、通知权限均为按场景请求；拒绝后不能反复强迫弹窗。
- 登录或授权完成后，用户原本准备执行的动作应自动恢复，不应要求重新操作。

### 13.8 页面与返回路径清单

为避免只画“主页面”而漏掉跳转稳定性，核心页面至少应覆盖以下路径：

- 地图首页 → 沿途服务面板 → 服务结果 → 地点详情 → 方式选择 → 对应导航模式。
- 地图搜索 → 搜索建议/历史 → 结果列表/地图结果 → 地点详情。
- 地点详情 → 收藏夹选择/新建收藏夹 → 收藏成功状态。
- 地图长按或地点详情 → 新建标注 → 可见范围 → 私存/好友分享/公开申请 → 审核状态。
- 发现页 → 地点帖/讨论帖详情 → 作者主页、评论、举报、分享、关联地点。
- 我的 → 我的标注/我的帖子/审核通知/设置与隐私。
- 消息 → 会话 → 地点卡片 → 地点详情；会话 → 创建/加入/退出位置共享。

每条路径都需定义：返回目标、未登录续办、权限拒绝、加载、空态、失败重试和内容被撤回后的表现。

### 13.9 质量与体验底线

- 对核心急需服务，交互优先级应支持用户在约 10 秒内完成“找到并开始导航”的目标；该目标是产品体验指标，不可在未测量前作为技术性能承诺。
- 关键触控区域不小于 44 dp；状态颜色必须配合文字、图标或结构提示。
- 地点、群名、标签、地址、城市名和用户内容需要长文本截断/换行策略。
- 用户输入、草稿、地点和已选导航方式在可恢复失败中尽量保留。
- 不得以“审核通过”“实时可用”“附近最近”等模糊文案掩盖数据来源、排序规则或状态不确定性。

### 13.10 给其他协作窗口的需求判断顺序

当需求出现歧义时，按以下顺序判断，不得先假设技术方案：

1. 是否直接服务旅游便利、旅游资源标注或旅游攻略/资源讨论？
2. 是否破坏游客优先、按需登录或隐私可见范围？
3. 是否会与三层审核、可信地点信息或公共地图投放规则冲突？
4. 是否属于首发已确认、待讨论候选，还是后续版本？
5. 若仍无法判断，记录问题并向用户询问，不可将个人推测写入产品基线。

### 14.3 全局导航与页面栈

#### 根导航

底部五栏仅存在于根页面：**地图｜发现｜消息｜收藏｜我的**。

- 当前栏目使用品牌蓝和明确文字/图标状态表示，不能只用颜色。
- 未读消息可在“消息”栏单独表现，不能占用地点可信确认绿或公共推荐标记。
- 根栏在全屏导航、地点详情、帖子详情、编辑、聊天、审核、权限和实时位置共享页面中隐藏。

#### 独立页面栈

以下页面从根页面进入，但有各自返回上下文：

- 搜索与搜索结果。
- 沿途服务面板与服务结果。
- 地点详情、导航方式选择、步行/骑行/驾车/公交地铁/打车五类出行状态。
- 收藏夹创建/编辑和收藏地点列表。
- 新建/编辑标注、可见范围、公开申请和审核状态。
- 帖子详情、评论、作者主页、举报、分享。
- 登录、手机号验证码、密码、微信登录、定位/相册/相机/通知权限说明。
- 好友申请、好友主页、私聊、群聊、位置共享。
- 我的标注、我的帖子、通知、设置、隐私。

返回行为规则：从卡片进入的详情页应返回原卡片所在的列表、地图视角或会话；登录和权限完成后必须续办触发动作；已撤回、无权限或已删除内容的返回页必须保留并提示原因，不可直接白屏。

### 14.4 地图首页设计结构

地图首页是首要入口，视觉优先级从高到低如下：

1. **搜索**：顶部城市/定位上下文 + 搜索框；支持地点、服务、地址、城市和标签。
2. **六项直接服务**：厕所、加油站、充电站、超市、景点、酒店必须在首页第一屏可见。
3. **沿途服务**：以显著横幅、常驻面板或上拉面板表达“全部旅行所需”，可进入停车场、充电宝、药店、医院、便利店、警务点、美食等服务。
4. **地图本体**：保留足够可视面积；当前定位、基础 POI、公共推荐点和结果标记必须可辨识。
5. **结果/操作卡片**：点击服务、地图点或搜索后显示；主操作始终是导航。

地图首页禁止事项：

- 不能把“沿途服务”藏在难发现的三点菜单或二级列表。
- 不能用过多浮层遮挡地图，导致用户看不到自己和目的地的相对位置。
- 不能把公共推荐标记、普通 POI、当前定位、未读消息和审核状态画成同一种图形或颜色。
- 不能为了推荐内容降低厕所、补能、停车等急需设施的首屏可达性。

### 14.5 地点结果、详情与可信组件

#### 地点结果卡片

结果卡至少包含：类别图标、名称、距离、地址/区域摘要、营业摘要、最近确认摘要和“导航”按钮。

- 急需设施卡片突出距离和导航；不以封面图抢占主操作。
- 旅游景点、酒店、美食等探索型结果可增加图片或社区摘要，但仍要保留距离与导航路径。
- 结果列表默认距离优先；筛选项可包括营业中、最近确认、类别特征等，但不得伪装成“实时可用”。

#### 可信状态组件

可信组件的前端展示必须依赖后端给出的状态和时间，不由客户端自行推断：

- 用户确认仅采集其实际见到的地点存在、入口、营业时间或错误信息；提交后记录来源与时间，不承诺立即改变主数据或公开状态。
- 未确认营业时间、无法计算距离、没有实时容量等状态必须明确显示未知/不可确认，并保留导航、纠错或稍后确认等可行动出口。

| 展示文案/状态 | 前端依赖的业务语义 | 禁止误用 |
| --- | --- | --- |
| 地点存在 | 有可展示的地点存在确认 | 不能等同于当前开放。 |
| 营业时间 | 结构化营业时间或明确未知状态 | 不能将缺失数据显示为营业中。 |
| 最近确认 | 最近一次有效确认的时间和来源摘要 | 不能展示确认者隐私。 |
| 审核中 | 对应审核流程尚未终结 | 不能显示为已公开或平台推荐。 |
| 平台推荐 | 已通过人工审核且存在有效公共投放 | 撤回投放后必须移除。 |

#### 地点详情页面模块顺序

1. 基础名称、分类、距离和地址。
2. 可信状态、营业时间、最近确认。
3. 主操作“开始导航”，以及出行方式/外部地图入口。
4. 收藏、分享、确认信息。
5. 照片、标签、注意事项、开放时间、适合人群、消费水平等补充资料。
6. 关联地点帖和旅行讨论内容。

### 14.6 导航模式设计规则

#### 通用规则

- 导航进入后隐藏根导航，保留退出、路线概览、当前方式和目的地信息。
- 方式切换、路线重算、定位异常、网络异常和到达目的地均有独立状态。
- 地图 2D/3D 呈现以可读性与方向判断为准；3D 只能帮助理解相对位置，不能遮挡路线、转向和安全信息。

#### 四种方式

| 方式 | 信息优先级 | 特别要求 |
| --- | --- | --- |
| 步行 | 下一转向、剩余时间、距离、道路/入口提示 | 入口、楼层或步行可达性信息优先。 |
| 骑行 | 路线、坡度/道路提示、剩余时间 | 避免在骑行中要求复杂输入。 |
| 驾车 | 下一转向、车道/道路、距离、剩余时间 | 驾驶模式大字号、低干扰、禁止社区输入。 |
| 公交地铁 | 线路、换乘、步行衔接、末班/运营信息（有数据时） | 数据缺失时明确说明，不能推测。 |
| 打车 | 目的地、预计车程、第三方服务可用性、跳转动作 | 不展示虚构价格/车型/订单；跳转失败提供外部地图或其他方式。 |

### 14.7 发现页与内容卡片设计

#### 发现页结构

- 顶部一级导航固定为 **推荐｜公开**；点击或横向滑动都可切换。推荐页保留当前位置/浏览城市和搜索入口；公开页保留地区/景点/类别筛选入口。
- 推荐页以最近搜索/浏览/收藏的景点、当前位置或浏览城市、内容质量和用户选择的偏好推荐旅游内容；需显示简洁推荐原因，并支持切换附近、全国热门和最新。
- 公开页二级导航固定为 **热点旅游资源｜热门标注分享｜旅游计划探讨**；地区与景点筛选采用“全国 → 城市 → 商圈/景区”的级联选择器，并允许直接搜索具体景点。
- 公开社区采用内容优先的论坛阅读结构：频道导航下按标题、作者、正文摘要、旅行话题/地点标签与互动行组织长列表，使用清晰分隔线而不是连续大卡片。可增加旅行问题与高质量回答详情，形成可阅读、可讨论的公共氛围。
- 公开社区不得复制任何第三方平台的品牌标识、图标、具体文案、榜单机制或视觉资产；“娱乐化”仅指更有参与感的公共讨论和内容节奏，内容仍须与旅行资源、目的地经验、路线、计划或标注相关。
- 公开页右上角必须提供始终可见的 **“＋ 发布”** 入口；该入口只在公开社区出现，不在地图首页、导航和驾驶模式中出现。未登录用户点击后进入按需登录，成功后续办“选择发布类型”操作。
- 发布第一步必须让用户选择：旅行讨论/提问、旅游资源标注分享、公开旅行计划。三种类型分别进入各自编辑和审核流程；不得使用一个通用表单弱化地点、照片、公开脱敏或审核资料的差异。
- 公开社区搜索必须在同一结果页区分综合、讨论、标注、计划和地点；地点结果主动作是查看/导航，讨论结果主动作是阅读/回答，计划结果主动作是查看/复制。前端不得把不同类型的结果点击到同一详情页。
- 信息流中必须一眼区分地点标注帖、旅行讨论帖与公开旅行计划。
- 地点标注帖可直接进入地点详情和导航；讨论帖可关联地点，但不能假设必有坐标。
- 公开旅行计划可进入计划详情并复制为私密可编辑副本；复制不修改原计划。
- 内容排序、推荐逻辑和城市范围由后端提供可解释字段，前端只负责展示和用户选择。

#### 三类内容卡片

| 卡片 | 视觉主次 | 必要信息 | 主要动作 |
| --- | --- | --- | --- |
| 地点标注帖 | 照片优先 | 地点名、城市/区域、作者、图片、简述、互动、审核/可见性摘要 | 查看地点、收藏、评论、分享。 |
| 旅行讨论帖 | 文字优先 | 标题/正文摘要、作者、城市/标签、互动、关联地点（如有） | 阅读、评论、收藏/分享、关注作者。 |
| 公开旅行计划 | 路线/日程摘要优先 | 目的地、天数、出行方式、地点数、作者、路线/日程摘要、互动与公开状态 | 查看计划、收藏、评论、分享、复制为我的计划。 |
| 旅行问题/回答 | 标题和正文优先 | 问题、目的地/话题标签、提问者、回答摘要、互动、关联地点或计划（如有） | 阅读回答、写回答、收藏、评论、关联地点导航。 |

地点帖的照片和地点信息应服务资源判断，不能只做旅游美图瀑布流；讨论帖必须保留正文阅读空间，不能被大图压缩为普通动态；计划帖不能只显示封面，应让用户快速判断天数、路线强度和可复制性。

### 14.8 标注与公开编辑流程

#### 页面拆分

1. 选择或确认定位点。
2. 填写名称和基础资料。
3. 选择可见范围。
4. 如公开到论坛，补充描述、照片和公开所需资料。
5. 提交后显示对应审核或发布状态。

#### 可见范围的界面语义

| 选项 | 可见对象 | 是否进入公开审核 | 前端提示重点 |
| --- | --- | --- | --- |
| 仅自己 | 创建者本人 | 否 | 可用于下次导航和个人记录。 |
| 指定好友 | 被选好友 | 否 | 可随时修改名单或撤回。 |
| 全部好友 | 当前好友关系内成员 | 否 | 不等于公开社区。 |
| 公开到论坛 | 所有符合分发条件的用户 | 是 | 需补充描述和照片，并展示审核流程。 |

- 前端不得将“公开到论坛”直接视为成功发布；提交后必须显示内容审核和地点审核状态。
- 私密标注在地图、收藏、聊天分享和个人页中的显示都必须遵从同一可见范围，不允许各页面自行放宽权限。

#### 标注管理页

- “我的标注”默认使用列表视图，并提供地图视图切换；列表优先承载筛选、编辑、审核进度和草稿管理，地图视图用于回看空间分布与继续导航。
- 筛选必须支持城市/区县、自定义收藏夹、草稿、仅自己、好友可见、公开、审核中和需补充资料。卡片至少显示名称、缩略图（有则显示）、地点/距离或城市、最后确认/更新时间、可见范围和审核状态。
- 卡片更多操作与详情页均提供编辑、导航、分享、修改可见范围、撤回公开、删除和地点纠错；不可用或已撤回内容必须保留状态说明，不能静默消失。
- 标注详情可提供“加入旅行计划”动作；加入后应由用户选择目标计划和日期，计划中仅保存受权限控制的地点/内容引用。后续撤回、删除或失去权限时，计划条目显示不可用原因并引导替换，不能继续泄露原标注资料。
- 修改已公开标注的地点、照片、公开文案或可见范围时，客户端必须展示影响摘要，并由后端返回是否需重新进入内容审核或地点公开审核；私密字段的普通编辑不应自动变更公开版本。

### 14.9 旅游计划设计与公开分享

#### 计划入口与列表

- “我的”内提供旅游计划入口；新建计划页同时提供“手动创建”和“AI 生成”入口，公开计划的卡片提供“复制为我的计划”。
- 我的计划列表区分草稿、已安排、进行中和归档；当前或即将出发计划优先展示。计划卡包含目的地、日期/天数（私密可见）、出行方式、地点数和当天状态。

#### 计划编辑与 AI 草拟

- 手动编辑以“按天日程 + 路线地图”组合展示，支持从地图、收藏、标注、地点详情、论坛地点帖和公开计划添加地点；地点可调整顺序、替换、删除并填写私密备注。
- AI 输入至少覆盖目的地、日期或天数、出行方式和旅行偏好；输出必须是可编辑草稿，并标明地点/路线来源或不确定性。用户可重生成整份或单日计划，AI 不得覆盖用户已确认修改。
- 计划地点与当天行程均有直接导航入口；调整顺序、方式或地点后，路线摘要必须重新计算并显式提示。

#### 公开计划与隐私

- 公开流程允许作者逐项隐藏真实出发日期、实时位置、同行人、私密地点和私人备注；公开版本默认用“第 N 天”表达，不暴露未选择公开的精确时间。
- 公开计划进入“公开｜旅游计划探讨”，支持查看、点赞、评论、收藏、分享、举报和复制。复制后新副本默认仅自己可见，保留来源归属但不允许反向修改原作者计划。
- 公开计划使用独立论坛内容审核状态；计划撤回公开或删除后，公开列表、搜索、分享页和收藏状态必须同步显示不可用/已撤回原因。
- 若作者修改已公开版本的路线、可见地点、图文或脱敏范围，客户端必须提示其变化会影响公开内容，并由后端返回是否需重新审核；私密原计划的普通编辑不应阻断用户继续使用自己的计划。

### 14.10 收藏页设计规则

- 首页签/页面标题明确显示当前城市、区县或收藏夹上下文。
- 默认城市归类与用户自定义收藏夹必须可同时存在；同一地点可被放入多个收藏夹。
- 地点卡优先展示距离、类别和导航，长按/更多操作再提供整理、移除或移动。
- 没有收藏时，空态应引导用户去地图、发现页或好友分享中保存地点，不表现为错误。
- 从收藏加入计划时，用户必须选择目标计划及日期；收藏本身不应被移动或删除。计划保存受权限控制的地点引用，后续地点不可用时应显示原因并支持替换。
- 删除收藏夹只移除该收藏夹与地点的组织关系，不得删除地点、用户标注、其他收藏夹中的同一地点或已存在的计划引用。

### 14.11 消息、好友与聊天页面设计

#### 消息根页

- 通知中心与会话列表要有清晰分区，避免审核结果、好友申请和私聊消息混在同一未读逻辑中。
- 通知项必须包含来源、时间、动作和可达目标；内容已删除或权限失效时显示不可用状态。

#### 好友体系

- 好友页至少包含好友列表、好友申请、好友主页和定向分享入口。
- 关注关系不应出现在好友私聊权限判断中；前端应从后端取得明确关系状态。
- 好友申请支持同意、拒绝、删除、拉黑/举报等基础边界；同意后才授予私聊、私密群邀请和定向分享权限。

#### 聊天与地点卡片

- 地点卡片需展示名称、分类、距离/区域、缩略地图或图片摘要和导航入口。
- 私密地点卡片不可因为截图、缓存或转发而绕过权限；打开时重新请求可访问内容。
- 群聊入口必须明确是私密邀请群，不用“附近群”或开放公共群的表述。
- 会话中的计划卡应展示计划摘要和可执行动作；私密计划、私密标注和已撤回内容打开时均由服务端重新鉴权，并在不可用时说明原因。
- 好友主页只能显示对该好友可见的标注、计划和内容摘要；好友关系不得作为读取“仅自己”内容的隐式授权。

### 14.12 实时位置共享页面

- 页面需直接展示参与者、共享状态、本人是否正在共享、发起者身份和退出按钮。
- 创建者关闭会话时，所有成员同时收到“本次共享已结束”的明确状态。
- 加入共享前显示对象和隐私说明；退出只停止自己的共享，不应默认退出聊天群。
- 定位不可用、网络中断、后台限制、参与者离开和会话过期必须有区分明确的界面状态。
- 前端地图只显示当前有效参与者位置；不绘制默认历史轨迹。
- 位置共享开始前须让每位成员主动加入；本人退出只停止自身上报和显示，发起者退出则关闭整场共享并向全体参与者推送结束状态。
- 群创建者解散私密群时，同时结束该群中正在进行的位置共享；群成员退出位置共享不等于退出聊天群。

### 14.13 我的、通知、审核与设置

- “我的”负责用户身份、我的标注、旅游计划、我的帖子、收藏入口、好友/关注、通知、设置与隐私。
- 审核结果在通知中心和相应内容详情中都能找到；两处展示同一业务状态，不能一个显示公开、另一个显示审核中。
- 设置页应包含账号、权限、定位与隐私、通知、黑名单/举报相关入口，以及后续可扩展的缓存/离线入口。
- 未登录的“我的”页面展示可浏览的引导和登录入口，不能让游客误以为核心地图功能不可使用。
- 收藏、标注、发帖、评论、关注、加好友、聊天、位置共享等写入或社交动作触发按需登录；认证完成后客户端必须恢复原页面、地点、筛选、草稿和待执行动作。
- 定位、相机/相册、通知权限均在对应场景前说明用途；拒绝定位时可搜索城市/地址，拒绝相册时可稍后选择上传，拒绝通知时仍可在通知中心查看状态。
- 通知中心按审核、互动和同行分区；审核结果应链接回具体内容与下一步动作。举报提交后显示成功回执，不承诺固定处理时限；内容不可用时按已删除、无权限、审核未通过、已撤回和网络错误提供不同恢复路径。
- “我的”聚合个人标注、收藏、计划、帖子、好友/关注、通知与隐私设置；我的帖子列表必须与通知中心共享同一审核状态，未登录状态须提供登录收益说明并保留游客核心地图能力。

### 14.14 前端与后端的数据对接约定

以下是业务展示契约，不限制 API 技术形态。前端不得通过猜测字段、客户端计数或 UI 分支推导权限和审核结果。

#### 最小地点展示模型

地点列表和详情所需数据语义至少包括：

- 稳定地点标识、名称、分类、坐标、地址、城市/区县。
- 距离值及其计算上下文；无法计算时明确为空而不是显示 `0 m`。
- 营业时间结构或“未知/不可确认”状态。
- 可信状态摘要：地点存在、最近确认时间、来源摘要、是否允许用户确认。
- 导航所需目的地信息与可用方式，不在 UI 中拼接供应商私有字段。
- 用户关系状态：是否已收藏、可否编辑、可否分享、当前可见范围。
- 公共推荐投放状态与有效性；仅有效投放的地点使用公共推荐视觉。

#### 最小标注/帖子展示模型

- 稳定内容标识、内容类型、作者、创建/更新时间、可见范围、审核状态。
- 地点关联（有则提供）、媒体摘要、文字摘要、互动计数和当前用户互动状态。
- 可执行动作集合，例如可编辑、可删除、可评论、可举报、可分享；前端不得仅凭作者 ID 或页面来源自行决定。
- 内容不可用时的原因分类：已删除、无权限、审核未通过、已下架、网络错误；不同原因给出不同恢复路径。

#### 最小旅游计划展示模型

- 稳定计划标识、作者/所有者、标题、目的地摘要、日程天数、出行方式、创建/更新时间、当前计划状态（草稿/已安排/进行中/归档）与可见范围。
- 按天路线摘要、计划条目顺序、每个条目的引用类型与可导航地点信息；删除或无权限的引用必须提供可恢复的不可用状态，不可由前端悄悄移除。
- AI 草拟元数据：是否由 AI 起草、生成范围、用户确认/修改状态和可重生成能力；前端不得把 AI 生成文本或路线当作实时事实。
- 公开版本状态、内容审核状态、公开脱敏规则、互动计数与“可查看/可复制/可编辑/可撤回公开”等后端下发的动作集合。复制计划接口返回新计划标识和所有权，前端不能通过复制原列表对象模拟成功。

#### 审核与可见性展示模型

- 内容审核、地点公开审核、公共推荐审核分别提供独立状态、用户可见摘要和下一步动作。
- 可见范围使用明确枚举而非前端文案比较；好友名单/授权名单由服务端作为权威来源。
- 后端状态变更后，前端的列表、详情、收藏、地图点和通知应能一致刷新或失效缓存。

#### 异步动作通用规则

- 收藏、点赞、确认、提交审核、加入/退出位置共享等动作都需要处理中、成功、失败和可重试状态。
- 失败后尽量保留用户输入与上下文；只有服务端明确拒绝时才回滚乐观状态，并展示可理解原因。
- 用户没有权限时，应给出登录、申请权限、返回上页或查看可公开替代内容等可行动出口。

### 14.15 前端验收清单

每个页面或功能在交付前至少检查：

- 是否存在加载、空数据、网络失败、权限拒绝、内容失效和长文本状态。
- 是否依赖了正确的可见范围、审核状态和当前用户权限，而不是静态模拟数据。
- 是否在游客、未登录后续办、已登录、被拉黑/无权限等状态下有正确入口。
- 是否保留地图视角、搜索词、筛选、草稿、目的地或会话等应保留上下文。
- 是否符合地图优先、急需服务优先、地点帖照片优先、讨论帖文字优先、计划可执行且可导航、驾驶低干扰的产品原则。

### 15.5 质量、数据与安全门槛

- **可用性：** 地图急需服务流程以“找到并开始导航”的完成时间、找点成功率和路线启动成功率验证；“约 10 秒”是体验目标，不能在未测量前作为性能承诺。
- **可信性：** 客户端只能展示后端给出的地点存在、营业摘要、最近确认、审核和推荐状态；未知即显示未知，不得伪造实时性。

- **内容安全：** 论坛、公开标注、公开计划、评论、图片和举报链路必须可审计；审核通过不等于自动获得公共地图投放资格。
- **AI 安全：** AI 只能起草可编辑内容，不能伪造地点事实、承诺实时可用、默认公开用户数据或覆盖用户已经确认的修改。

- 修复已通过前端路线/类型检查，并已重新构建 Android Release APK；真机验收必须验证：服务面板打开时轻点未覆盖地图区域会收起面板，面板收起后地图可拖动、缩放且无假装饰覆盖。
